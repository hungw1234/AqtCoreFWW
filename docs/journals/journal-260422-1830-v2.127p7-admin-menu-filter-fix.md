# v2.127p7 — Admin Menu Page Fix + System-Menu Edit Guard

## Context

User báo `/admin/menus` "Không thấy dữ liệu". Trong khi sidebar (`/my-menus`) hoạt động bình thường.

## Root Cause

Filter mismatch giữa 2 handler cùng query `identity.AppMenus`:

| Handler | Filter |
|---|---|
| `MenuService.LoadFromDbAsync:82` (sidebar) | `m.TenantId == null \|\| m.TenantId == ctx.TenantId` ✅ union |
| `ListMenusQueryHandler:18` (admin page) | `request.TenantId == null \|\| m.TenantId == request.TenantId` ❌ `request.TenantId` non-null → clause đầu false, clause sau `null == <GUID>` false → zero rows |

Tất cả menu seeded trong `E2ETestDataSeeder.Menus.cs:260` gán `TenantId = null // System menus — all tenants`. Tenant user login → `ResolveTenantId()` trả GUID non-null → filter loại sạch.

## Fix (Option B — minimal + guard)

### BE — 2 files
1. `ListMenusQueryHandler.cs:20` — đổi `request.TenantId == null` thành `m.TenantId == null`. Thêm comment anchor "Matches MenuService.LoadFromDbAsync filter" để tương lai grep cả 2 handler khi drift xuất hiện.
2. `MenuCommandHandlers.cs` — inject `ITenantContext`, guard trong `UpdateMenuCommandHandler`: nếu `menu.TenantId is null && !tenantContext.IsSystemAdmin` → return `ForbiddenError` 403. Defense-in-depth kết hợp với FE disable.

### FE — 1 file
3. `menu-admin-page.tsx` — thêm `usePermissions().hasRole('SystemAdmin')` detection, render tag `Hệ thống` (geekblue) cho row `tenantId=null`, disable nút Edit + tooltip "Menu hệ thống — chỉ SystemAdmin mới sửa được" khi user không phải SystemAdmin. UX tương đồng `/admin/rtbf` handling.

## Notes & Lessons

1. **Test ≠ feature working** — filter bug này tests infra handler riêng lẻ sẽ pass (handler query đúng theo spec filter được viết) nhưng cross-handler consistency với `MenuService` không có test → silent drift. Pattern lesson đã ghi memory `feedback-tests-pass-feature-fails.md` từ trước.
2. **Grep-anchor comment** thay vì integration test — với fix 1 dòng, cost viết integration test "2 handlers return same global-menu set" cao hơn giá trị. Comment "Matches MenuService.LoadFromDbAsync filter" là compromise giúp reviewer tương lai catch drift qua code review.
3. **Sidebar vs admin page** được phục vụ bởi 2 handler khác nhau — kiến trúc chia nhỏ này là root cause của drift. Nếu consolidate (1 handler chung + project shape khác nhau), class bug này biến mất. Deferred vì YAGNI.
