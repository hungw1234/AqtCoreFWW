## Key decisions + rationale

**Query design (Phase 2):** read-time keyset (no projection table), sort by InstanceId DESC (seekable on index). Red-team BLOCKER: keyset over per-instance `MAX(TransitionedAt)` aggregate is NOT index-seekable → would force mandatory write-time projection escape-hatch. Choosing InstanceId kept it read-time + simple. Index `IX_WorkflowInstanceHistories_TransitionedBy_InstanceId` drives the query; scales with participation, not total rows (billion-scale NFR).

**Verify-gate (Phase 1):** empirical DB probe BEFORE coding corrected 3 critical plan assumptions: (a) table is `WorkflowInstanceHistories` (PLURAL), (b) history has NO TenantId column → tenant gate via `WorkflowInstances` JOIN, (c) `WorkflowInstance`+`WorkflowState` ARE `ISoftDeletable` (EF global filter applied; raw SQL must add `IsDeleted=0` explicitly). My earlier "not soft-deleted" check was wrong because I read only the entity config, not base-class + global-filter. Code-reviewer caught it; I re-probed with full column query and confirmed — revised per evidence (review-audit rule §1: verified decision locks, audit must bring new data to reverse).

**No total count:** HasNextPage via N+1 keyset, not COUNT(*). Keeps it scalable.

## Lessons (honest meta)

1. **Verify-gate earned credibility:** Phase 1 DB probe corrected 3 critical plan errors BEFORE code. Reading only entity config missed global `ISoftDeletable` filter that EF applies silently; my first probe filtered the column list so `IsDeleted` was invisible. This is a brittle pattern in EF — global filters are low-visibility. Lesson: always run full `SELECT *` on the table itself + check Entity base classes + grep `HasQueryFilter` in DbContext.

2. **Live HTTP test beat SQL-direct:** `/api/v1/workflow/instances/my-processed` returned 500 on curl — turned out to be AuthServer (5002) DOWN (env failure), not Phase 3 code. SQL-direct had already proven the query returns the right BP instance row. Lesson: SQL-proof ≠ HTTP-proof; distinguish env failures from code before "fixing". But also: don't over-assume correctness from SQL when auth/infrastructure still unchecked.

3. **Provenance honesty:** Phase 3 BE files (`GetMyProcessedInstances/`, migration `.Designer.cs`) were ALREADY in the working tree at session start (git status snapshot + timestamp 04:52 predating this session's Phase 3 work). Fullstack-dev subagent refined/verified; my edits (IsDeleted, LEFT JOIN, EntityType filter, index covering columns) are this-session. I committed the verified state, not falsely claimed authorship.

4. **Ops-level friction:** 
   - Parallel `dotnet run` of Auth (5002) + API (5001) race on shared `AqtCoreFW.Infrastructure.dll` (CS2012 file lock) → start sequentially, not in parallel.
   - Vault dev-mode is in-memory → secrets lost twice mid-session; re-seed via `docker compose run --rm vault-init`.
   - Orval regen flips line-endings on 15 unrelated generated files → commit only 2 content-changed files as `chore(api)`, revert the CRLF churn.

5. **"No consumers" is an architectural signal:** the live inbox hook had zero FE consumers because the dead `/cases` endpoint was wired instead. This wasn't a code-quality miss — it was a broken contract; the hook existed but the FE never found it. Lesson: when "dead code" is an endpoint, trace where it WAS wired and why it stopped being called. Often the new consumer never landed, not the endpoint was wrong.
