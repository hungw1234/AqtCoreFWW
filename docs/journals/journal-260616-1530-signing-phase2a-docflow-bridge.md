# Signing Foundation Phase 2a — USB DocFlow Bridge

**Date:** 2026-06-16 ~15:30 ICT · **Flow:** `/cook "Phase 2" --auto` (code mode) · **Scope:** BE Identity + Api host + FE digital-signature · **Commit:** `7f6f7d6e` (3 ahead of origin/main, not pushed)

## What shipped
Wired the Phase-1 `SigningRequest` scaffold to actually execute, bridging it onto the already-shipped VGCA USB DocFlow round-trip. The unit was deliberately reduced to a **thin 2a bridge** after an audit-at-slice-start (the plan's Phase-2 body is a pre-red-team draft conflating 2a / 2b / Phase-6 concerns).

- **`ISigningExecutionStrategy`** — execution surface kept *separate* from the routing-only `ISigningStrategy`. This preserves the deliberate Phase-1 decision to ship no throw-stubs: `DetachedDataSigningStrategy` / `PadesAssemblerSigningStrategy` still implement only the routing predicate (no `ExecuteAsync`), and the orchestrator surfaces a typed failure if a matched strategy isn't executable yet.
- **`DocFlowSigningStrategy.ExecuteAsync`** — executes by delegating to the shipped `InitiateDocFlowCommand` *via MediatR*, NOT by calling `IDocumentSigningWorkflow` directly. That command's validator carries the tenant-prefix storage-key guard (the cross-tenant-read defense) and the audit entry; the unified path must reuse them, not re-implement.
- **`SignatureOrchestrator.RequestSignatureAsync`** — create (in memory) → execute strategy → link underlying record → save, so the request row is never left unlinked and a failed/throwing execution writes no orphan row. Returns `Result<RequestSignatureResult>`.
- **Endpoints** — `POST /api/signing/request` (Auth + RequiresMfa) + `GET /api/signing/request/{publicId}/status` (read-time projection poll). tenantId/userId from auth context (never body); baseUrl server-side; self-sign (AssignedSignerId = caller).
- **FE** — `createSigningRequest`, `getSigningRequestStatus`, and the `useSigningRequestStatus` poll hook (2s interval, cap 60 polls + `timedOut`, `resetQueries` retry — mirrors `useFileScanStatus`). camelCase + string-enum types verified against the real serializer.

## Decisions / lessons
- **Audit-at-slice-start saved a 2.5× over-build.** Three parallel Explore scouts ground-truthed the plan's Phase-2 against the code: the multi-signer BP "sign document" transport genuinely does NOT exist (`BpRunSignaturePayload` is detached-only, no BP↔signing link, no step type) → confirmed net-new **2b**; the form-gen signer-anchor render needs a signer-role schema that `FormField` lacks → couples to 2b; the authoritative cert==signer bind needs to PARSE the signed PDF → **Phase 6 sandbox** (doesn't exist). Only the bridge was actually shippable now. Surfaced the scope to the user (chose thin 2a) rather than building the whole pre-red-team phase.
- **The security landmine was the C2 boundary.** The tenant-prefix storage-key guard lives in `InitiateDocFlowCommandValidator`, NOT in `DocumentSigningWorkflow`. A unified path that routed straight to the workflow would have *bypassed* it. Routing the strategy through the command (MediatR) keeps C2 + audit intact for free — the deciding reason for that layering, not ceremony.
- **Two parallel signing stacks existed; this bridges them.** Stack A (FE → `/docflow/initiate` → `DocumentSigningWorkflow` → `SigningDocFlowRecord`) already signs USB PDFs end-to-end. Stack B (`SigningRequest` + orchestrator + router) was a Phase-1 scaffold with no execution seam and 0 `LinkUnderlying` call sites. 2a is the seam that makes Stack B real on top of Stack A.
- **Code-review H1 (fixed in-slice, new data).** The first cut threw `NotSupportedException` / `InvalidOperationException` for routing + validation failures. The global exception handler maps neither → every bad-input/tenant-rejection became HTTP **500**, and the inner `ValidationError` was collapsed into a generic message (losing 422). Reshaped the orchestrator + strategy to `Result<T>` and propagated the inner errors with their type intact → `ToApiResponse` now maps unsupported-route → 400, tenant-prefix rejection → 422, not-found → 404. Kept the fix local (no global-middleware blast radius). A genuine invariant violation (success with no record id) still throws → 500, correctly.
- **Additive contract discipline.** `DocFlowResult` + `InitiateDocFlowResultDto` gained `long? RecordId = null` (optional-with-default → existing positional callers + tests unaffected). The `RequestSignatureAsync` return-type change Guid→`Result<RequestSignatureResult>` was safe only because grep confirmed the single production caller is the new controller.
