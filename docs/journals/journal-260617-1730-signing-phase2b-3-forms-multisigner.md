## What shipped
The deferred Forms sub-slice, run now that Docker is up for real-SQL Integration. A form template declares named signer roles (`FormTemplateSignerRole` child table, mirrors `FormField→FormFieldOption`); a multi-signer submission captures per-signer evidence in an additive `FormSubmissionSignerEvidence` child collection; the existing single-signer scalar path (6 columns + `RecordSignatureEvidence`) is byte-for-byte untouched (additive-first, user-locked). ## The real value was in what verification surfaced — three findings, all from running on real SQL
1. **A deferred-verification item was a real ship-blocker, not a benign gap.** 2b-2 shipped with Docker down and left NEW-N2: "re-run Integration when Docker up — supersede/unique only on EF-InMemory." That re-run immediately failed whole-app DB bootstrap with `Incorrect syntax near 'NOT'`: the 2b-2 filtered unique index used `[Status] NOT IN (2, 3, 4)`, and **SQL Server filtered-index predicates do not accept `NOT IN`**. EF-InMemory never applies the filter SQL, so it was invisible until real SQL. It would have failed *every* real deployment (dev cutover, prod), not just tests. Fixed to the equivalent active-set enumeration `[Status] IN (0, 1)` across all 4 occurrences (config + migration + Designer + snapshot). **Lesson: "re-verify when the environment is back" is not paperwork — the deferred check caught a P0 the InMemory suite structurally could not.**
2. **InMemory-vs-real divergence, second instance, same slice.** The submit-handler routing read `template.SignerRoles` but the 3 repository load methods lacked `.Include(t => t.SignerRoles)`. Unit tests (EF-InMemory, entity tracked with the collection populated in-memory) passed; the real repository load returned `Count == 0` → multi-signer templates silently fell to the single-signer scalar path. Only the integration test exercising the real load path caught it. **Lesson: navigation-dependent branching is invisible to InMemory unit tests that hand-build the aggregate; it needs a real-repo integration assertion.**
3. **A domain mutator with no caller = dead feature.** `FormTemplate.AddSignerRole(...)` existed but nothing invoked it — no command, no controller, no seeder. So `SignerRoles` was always empty in production and the entire multi-signer branch was unreachable. The integration test (which tried to *use* the feature end-to-end via an authoring endpoint) surfaced it as a 404; unit tests that construct domain state directly never could. Resolved by adding the authoring endpoint (user-approved scope expansion). **Lesson: a feature is only as real as its write-path; an end-to-end test that drives the feature the way a user would is what exposes missing seams.**
