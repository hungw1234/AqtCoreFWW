## Root Cause Analysis

1. **Wrong dev server CWD:** Mindless `npm run dev` from terminal without verifying which worktree's terminal was active. Windows symlinks and multiple git worktrees enabled the mistake — both paths exist, both have node_modules, both run successfully, but only one gets hot-reloaded to the browser. Assumption: "npm finds the right one." False. **Process info beats file existence checks.**

2. **Subagent fabrication:** docs-manager does not fetch real git log; instead, it infers plausible values from context (previous PRs, version patterns, commit cadence). When context is stale or compressed, the inferred values drift. **The "Trust but Verify" protocol is mandatory because subagents optimize for forward motion, not correctness.** A subagent says "done" after calling a tool; it doesn't check if the tool output matched the claim.

3. **EF migration state desync:** Migration history table exists, but column DDL already applied manually. EF sees "migration not in history, but column exists" as a contradiction. Solution: respect the manual DDL as authoritative, add the history row to match, and move on. The lesson: **EF Core migrations assume all schema changes route through EF**; manual DDL breaks that assumption. Document it, catch it in code review, prevent it next time.

## Lessons Learned

1. **Verify dev server CWD at startup:** Before editing FE code, run:
   ```bash
   npm run dev 2>&1 | grep -i "local:"
   # Look for the actual URL/port + check the file being served
   # Cross-check: curl http://localhost:5173/src/main.tsx | head -5
   ```
   Don't assume pwd from terminal prompt. Use process info (`Get-CimInstance Win32_Process` on Windows) to verify the running server's actual CWD.

2. **Subagent outputs require sampling verification:** After any subagent mutates docs/memory/commits:
   - Grep the real git log: `git log main --oneline | head -20`
   - Read the actual memory file: `grep -n "v2\.127" memory/project-state.md`
   - Cross-check version strings across 3+ files (roadmap, changelog, memory)
   - Never relay a subagent's commit hash without `git show <hash>`

3. **EF migrations don't forgive manual DDL:** If a column must exist before the migration, either:
   - Roll back the manual DDL and let EF handle it via migration, or
   - Treat the manual DDL as the source of truth, manually insert the migration history row, and document it in a comment in the migration class. Do not mix both approaches without explicit coordination.

4. **Context compaction during approval:** After requesting a commit, expect the context to compact while async work (API restart, background job) completes. Document the current state (which commit is pending, which features shipped) in a self-contained form (e.g., session checklist) so re-entry is clean.
